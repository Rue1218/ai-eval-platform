## 1. 目标与范围

本规范定义平台如何通过标准 MCP 调用媒体生成能力，并允许管理员从前端管理连接、选择生图和视频模型。实现目标是可配置、可恢复、结果可追溯，同时控制 API 进程负载与 Agent 上下文增长。

本次明确采用 Streamable HTTP。浏览器通过平台 REST 管理配置、通过现有 `/ws/agent/v2` 接收运行事件；MCP 连接由服务端管理。Streamable HTTP 描述消息传输方式，不表示图片逐像素或视频逐帧实时生成。

本期覆盖：受控 MCP 服务、工具发现、协议档页面的媒体模型配置、Qwen 生图与 HappyHorse 视频提交/查询，以及 AgentLoop 图片缩略图和视频预览卡。视频创建只返回上游任务 ID；尚未实现平台级媒体任务表、文件归档、平台文件播放器与 Worker 轮询。首期不扩展为任意插件运行平台，不启动 stdio 子进程，不自动兼容旧 HTTP+SSE 传输，不引入 LangChain。

### 1.1 现状与差距

### 1.2 与内部 MCP 规范的关系

沿用[内部 MCP 与工具契约设计规范](./AI测试与评估平台-内部MCP与工具契约设计规范.md)的注册表、权限、输入输出校验和统一错误原则。该文的“进程内不实现 JSON-RPC”继续适用于 `InProcessProvider`，不适用于本次新建的远程传输边界。

远程客户端须实现其声明支持的 MCP 版本和能力。Tools、Resources、Prompts 是可协商能力，不要求每个服务同时提供三者；不能把“必须实现全部三原语”作为合规判据。

本次是用户明确提出的远程媒体 MCP 扩展。已实现的 REST 配置接口与工具目录已回写 [API 契约](./AI测试与评估平台-API.md)；不新增浏览器 WS 字段，也不创建媒体任务状态机。默认关闭，只有保存完整配置并启用后才向通用 Agent 注入媒体工具。

## 2. 架构与职责

当前调用顺序：用户提出生成需求 → 通用 Agent 调用已授权媒体工具 → API 通过固定 Compose 私网 Streamable HTTP 调用媒体 MCP → 上游媒体模型执行 → 工具结果回填当前 Agent 回合。图片直接返回上游临时地址；视频创建返回任务 ID，后续用 `video.status` 查询。

| 组件 | 必须承担的职责 |
| --- | --- |
| 前端 | 配置表单、脱敏状态、模型能力参数、真实连接测试、任务及资产展示 |
| API / Harness | 用户鉴权、工具权限、Streamable HTTP 调用与结果投影；不等待整段视频生成 |
| 后台执行器 | **尚未接入媒体**；后续承担持久化任务领取、轮询、取消对账和下载归档 |
| MCP 客户端 | 协议生命周期、目录快照、工具调用、结果转换、连接释放 |
| 媒体 MCP 服务 | 稳定工具契约、模型适配、上游任务寻址；自建时提供约定的模型配置接线 |
| PostgreSQL / 文件存储 | 任务状态及配置版本事实、文件归属与可访问性 |

首期建议新增独立的媒体任务实体，由现有 Worker 基础设施增加执行分支，不强行继承评测任务的“先评后压”和唯一活跃评测索引。表结构、领取租约及事件桥必须通过设计与迁移落地后才能启用。

平台只设置一个任务推进责任方。MCP 服务若负责上游轮询，Worker 只查询该服务；不得两端同时轮询同一供应商任务。

## 3. Streamable HTTP 接入规则

### 3.1 生命周期与能力

客户端依次执行 `initialize`、检查协议版本和能力、发送 `notifications/initialized`，再发现及调用工具。会话失效后重新初始化；只使用双方协商成功的能力。平台首期不声明 sampling、elicitation 或 roots，不接受远程服务借此调用模型或读取本地目录。

版本不支持、缺少必要工具能力时连接测试失败，不以“HTTP 200”代替协议成功。依据：[MCP 生命周期](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle)。

### 3.2 传输边界

- 一个 MCP 地址承载 JSON-RPC；POST 的 Accept 同时支持 `application/json`、`text/event-stream`，客户端解析两类响应。
- 服务未提供 GET SSE 时，405 是合法能力表现，不能单凭此认定连接失败。
- 按协商结果发送 `MCP-Protocol-Version`；服务返回会话 ID 后，后续请求携带 `MCP-Session-Id`。
- 支持服务提供的恢复游标时，按 `Last-Event-ID` 恢复；没有恢复能力时不声称可以无损重放。
- 连接关闭不代表业务取消；显式取消 RPC 也不自动证明上游生成任务已终止。
- 关闭或失效时释放客户端资源；按服务支持情况终止远程会话。

依据：[MCP Streamable HTTP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)。优先复用经版本锁定与兼容测试的官方 SDK，不另造 SSE/JSON-RPC 解析器。新增依赖须验证现有 FastAPI、Starlette 和异步生命周期兼容性。

### 3.3 平台连接管理策略

连接资源按服务、配置版本及认证身份隔离，有上限地复用；不能跨用户混用有用户状态的 MCP 会话。连接和目录不得每个 token 或每次状态刷新重建。分别设置连接超时、RPC 超时与业务任务截止时间，进度通知不能无限延长总截止时间。

目录分页完整读取后校验并原子替换。收到目录变化通知时刷新下一回合快照；进行中的 Agent 回合保持已选工具定义稳定。权限撤销或服务禁用仍须立即在执行门禁生效。

## 4. 配置契约：服务连接与媒体模型分离

已实现媒体配置接口为 `GET/PUT /api/mcp/media-config`，请求和响应字段见 API.md；其余通用服务登记字段仍是后续候选，不能据此增加未登记的 REST 路径。

### 4.1 MCP 服务配置

| 字段 | 含义与约束 |
| --- | --- |
| `id` / `name` / `version` | 稳定标识、展示名、并发更新版本 |
| `endpoint` | 管理员登记的完整 MCP 地址；禁止由模型工具参数覆盖 |
| `transport` | 首期固定 `streamable_http` |
| `auth_type` / `credential_ref` | 声明认证方式及服务端凭据引用；凭据只写不回显 |
| `enabled` | 保存、连通、启用三个动作分离；测试通过不自动授权工具 |
| `connect_timeout_s` / `request_timeout_s` | 管理端配置的有界超时 |
| `allowed_tools` | 发现后由管理员启用的工具白名单 |
| `last_check` | 最近检测时间、结果及脱敏错误；不是无限有效的健康证明 |

MCP 认证凭据与媒体模型 API Key 分开管理。不得转发浏览器 Cookie、平台会话令牌或模型 API Key 给任意第三方 MCP 地址。第三方若要求 OAuth，必须通过对应授权流程接入；首期若尚未实现该流程，明确标记不支持，不能用任意 Header 冒充兼容。

### 4.2 媒体模型配置

| 字段 | 含义与约束 |
| --- | --- |
| `id` / `version` / `name` | 模型配置标识、不可变修订版本、展示名 |
| `media_kind` | image 或 video；分别选择默认启用项 |
| `server_id` | 绑定哪个 MCP 服务 |
| `adapter_type` / `model` | 经实现的媒体协议适配器和实际模型 ID；仅改字符串不代表任意模型可用 |
| `upstream_endpoint` / `credential_ref` | 仅在自建服务或约定配置接口支持时可编辑 |
| `capabilities` | 支持的参考图、首尾帧、尺寸、比例、时长等，经服务或适配器验证 |
| `defaults` | 能力范围内的默认参数；不能注入 URL、身份或认证字段 |

默认配置被替换后仅影响新受理任务。已入队任务固定模型和参数版本；恢复不能静默切到新模型。凭据轮换以受控引用处理，禁止将明文复制进任务快照；凭据被撤销时如实报错。

### 4.3 自建与已有第三方服务

MCP 未定义通用模型管理接口，不能假定 `models/list` 或 `set_model` 是标准方法。

- **自建服务（建议方案）**：平台配置为单一事实源。受控媒体服务通过私有配置通道获取版本化配置；MCP 调用只携带获授权的配置引用，模型不可传任意上游地址或密钥。
- **已有服务**：按它公开的工具 Schema 或管理接口绑定模型。若只提供固定模型，前端标明“由服务端管理”，只允许切换服务/工具绑定；不能展示保存后无效的模型输入框。

服务部署方式、首批生图/视频模型及具体接口尚未确定。本规范可先落地共用边界，不视为用户已选择自建或某个供应商。

## 5. 前端操作规范

入口固定为“协议档 → MCP 与工具”，沿用现有页面，分服务连接、媒体模型和工具目录三个区域，不新建平行管理入口。

1. 新建服务：填写地址与认证 → 保存 → 测试初始化及目录发现。
2. 审阅工具：展示远程名称、说明、输入输出 Schema 和平台授权状态 → 勾选启用。
3. 配置模型：选择生图/视频、服务及支持的模型 → 设置默认参数 → 保存版本 → 设为默认。
4. 普通连接测试不生成收费内容；独立的“试生成”明确展示当前模型和输入，用户操作后才提交。
5. 编辑密钥时留空表示不修改，清除使用独立明确动作；响应仅返回是否已配置。
6. 区分未配置、已禁用、检查中、可连接、检查失败；工具不存在、认证失败、模型能力不支持须有不同说明。

保存配置后服务端重新校验能力和权限。前端不得仅凭模型名猜测参数，不承诺从 MCP 自动发现所有可用模型。更新使用版本校验，避免两名管理员互相覆盖。

## 6. 工具契约与 Harness 接线

### 6.1 标准边界

远程目录采用 MCP 的 `inputSchema`、可选 `outputSchema`。结果解析 `content`、`structuredContent` 和 `isError`，经边界适配为平台工具结果。远程 annotations 仅供提示，不能替代平台权限。依据：[MCP Tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)。

远程 Schema 使用支持 JSON Schema 2020-12 的校验器；旧的内部关键字子集不能直接冒充完整支持。远程引用不联网加载；本地引用有界解析。无法安全解析或投影给当前模型的 Schema 明确标记不兼容，不静默丢失约束。输入在派发前校验；远程输出违约归一为 UPSTREAM，自有适配代码违约归一为 INTERNAL。

### 6.2 媒体工具的逻辑契约

下列是平台媒体适配层的候选逻辑工具名，不要求第三方服务使用相同名称；映射由后端登记，工具 ID 不由模型拼接。

| 逻辑工具 | 模型可提供的业务输入 | 结果 |
| --- | --- | --- |
| `image.generate` | prompt、可选 HTTPS/Data URI 参考图、size、count、prompt_extend | `succeeded`、模型名、临时图片地址 |
| `video.create` | prompt、必填首帧 HTTPS/Data URI、resolution、duration、watermark | 上游异步任务 ID 与任务状态 |
| `video.status` | 上游任务 ID | 真实上游状态；成功时临时视频地址 |

当前工具不创建平台媒体任务，因此尚未提供跨重启的任务归属和取消；`video.status` 直接查询上游任务 ID。媒体参数只开放注册字段；参考图首期仅支持 HTTPS 地址或受大小上限保护的图片 Data URI。会话附件 file_id 的归属转换与平台资产归档留待媒体任务阶段实现。

注册工具后仍须完成 AgentLoop 白名单、专家能力交集、调度器和结果投影接线。仅在工具目录显示不算接入完成。`transport=mcp` 的工具走统一 Host 边界，不在 Agent 节点直接调用供应商 SDK。

执行会产生费用，平台按权限与预算策略裁决；远程 `readOnlyHint`、工具说明或模型文本不能绕过门禁。

## 7. 媒体任务：幂等、恢复与取消

### 7.1 生命周期候选

常规路径为 queued → running → succeeded / failed。队列中可直接取消；运行中先记录取消意图，只有得到上游终止证据才标记 cancelled。结果不明时保留 outcome_unknown 待对账，不冒充失败、取消或成功。

任务至少保存：平台任务 ID、发起人、会话及工作区引用、工具与参数摘要、配置版本、幂等键、远程任务 ID、领取租约、执行状态、取消意图、截止时间、资产引用和安全错误信息。具体表和枚举须回写 API/数据库设计并通过 Alembic 迁移。

### 7.2 幂等与崩溃窗口

- 相同用户、会话、逻辑请求的重复提交返回同一任务；同一幂等键配不同参数拒绝。
- Worker 领取使用租约与条件状态更新，恢复后先查询已记录的远程任务。
- 已发送生成请求但尚未拿到任务 ID 时崩溃：若上游支持幂等键则用同键查询/重试；否则标记结果不明并对账，禁止盲目重新生成。
- 超时、HTTP 断开、SSE 重连和进程重启都不是重新收费提交的充分理由。
- 取消尚未执行的排队任务不得调用供应商；取消运行中任务若上游不支持，告知“已停止等待/仍在上游运行”的实际状态，不展示“已取消”。

### 7.3 进度和事件

有通知或受控回调时优先使用，缺少时由后台有界轮询并退避。Agent 无需自动循环调用 `media.status`，前端也不高频轮询整个会话。

原始生成工具在受理后完成，后台媒体任务继续执行；Agent 回合结束与媒体任务结束是两个不同事实。没有产物时只能说“任务已提交”，不得说“文件已生成”。完成事件以任务 ID 关联原卡片，不伪造尚未运行的助手答复。

持久任务与文件终态必须可通过刷新/断线重连恢复；细碎进度允许合并且不必全部落库。复用 WS v2 事件信封，新事件及字段须先登记 API.md 和事件词汇表。MCP 远程游标与浏览器 WS 游标分别管理。

MCP 的 task-augmented 调用属于额外协商能力；首期不默认依赖。第三方若只提供长时间同步生成调用，由后台执行器等待，并明确其取消、幂等和重启恢复限制。

## 8. 文件与媒体结果

模型历史只记录任务摘要及文件引用，不保存生成视频 Base64 或整段二进制。MCP 传输若返回内嵌内容，在入口按大小限制解析并归档，不直接透传到聊天历史。

首期预览复用既有 `tool.result.display.result_preview`，不增加浏览器 WS 字段：前端只解析 `image_urls`、`video_url`、`status`、`model` 与 `upstream_task_id` 五个登记字段；图片与视频地址必须为不含账户信息的 HTTPS URL。图片懒加载缩略图，视频仅在 `video.status` 返回成品 URL 后显示原生播放器；`video.create` 的 `PENDING` 只显示任务状态。前端不轮询、不自动提交或重试生成，避免重复收费和 API 压力。

归档后的逻辑资产至少具备 file_id、文件名、MIME、字节数、归属和平台访问地址；视频按可用信息补充时长与封面。图片使用预览卡，视频使用播放器和下载入口。浏览器播放须具备文件鉴权及 Range 支持，不因引用外部临时 URL 暴露上游凭据。

上游临时链接不是持久成功证据：完成下载、校验类型/大小、登记归属后才将平台任务置为 succeeded。归档失败可重试拉取已有产物，不能重新生成。下载过程使用流式写入与大小上限，失败清理临时文件，并受工作区配额约束。

第三方无法直接访问平台 file_id 时，使用经归属校验的受限上传或短期下载授权，不能把平台私有路径当作远程可读地址。首期不通用开放任意 MCP `resources/read`；资源链接按明确支持的方案处理。

## 9. 安全、错误与资源控制

### 9.1 连接与凭据

管理接口仅管理员可修改；普通使用者仅调用已授权工具。地址保存和实际连接均校验目标，重定向逐跳校验，避免 DNS 变化和重定向绕过。公网使用 HTTPS 且验证证书；私有部署仅允许明确登记的内部服务目标，不全面放开内网地址。

自建服务验证认证及不合法 Origin，限制可访问配置与资产。密钥加密保存，日志不记录 Authorization、签名 URL、提示词全文或大文件内容。服务端返回的说明、资源和工具结果均作为外部数据处理。

### 9.2 错误映射

| 情况 | 平台错误 |
| --- | --- |
| 本地参数不合法、未启用或能力不支持 | VALIDATION |
| 当前用户无权访问任务、文件或配置 | UNAUTHORIZED |
| 目标未获准 | WHITELIST |
| 预算耗尽 / 并发额度耗尽 | BUDGET_EXCEEDED / CONCURRENCY |
| 缺少平台审批 | NEED_APPROVAL |
| 资源不存在 | NOT_FOUND |
| MCP 认证失败、协议响应异常、远程工具失败 | UPSTREAM（远程凭据错误不伪装成平台登录失效） |
| 超出等待期限 | TIMEOUT；业务结果另行对账 |
| 平台自身执行或持久化异常 | INTERNAL |

MCP JSON-RPC 错误与 `isError=true` 的工具业务错误分开解析，最终映射到平台既有十大错误码。对浏览器只返回安全说明；协议码及必要诊断留在受限日志，不能透传 SQL、堆栈或供应商原文。

### 9.3 资源与缓存

按用户和服务约束并发生成数、队列长度、输入文件大小、输出字节数及业务截止时间。具体默认值依据首批模型实测登记，不把生成耗时固定为短工具的 30 秒。

工具名称、顺序与 Schema 在回合内固定。替换媒体模型通常只修改后端配置引用，不将每个模型列成独立工具；能力收窄仍须执行校验。进度更新进入任务状态，不反复改写系统提示词。禁用服务即时阻止新派发，正在运行的任务保留查询与取消所需的最小受控通道。
