# AI 测试与评估平台 — 模型思考模板自动继承实施方案

> 版本：V1.2 ｜ 审查日期：2026-09-15
> 状态：实施中；产品与接口契约已先回写至 [PRD](./AI测试与评估平台-PRD.md) V1.23 与 [API 契约](./AI测试与评估平台-API.md) V2.1。
> 产品决策：采用供应商、协议和模板配置驱动新增模型；用户点击“测试并添加”时，平台使用该模板向所选模型发送最小真实请求，验证通过才保存。暂不建设无人触发的文档抓取、智能体自动生成模板或后台批量探测。
> 权威边界：接口路径、字段名与错误码以 API 契约为准；本稿说明实现边界、模板治理和后续演进。

## 1. 问题与目标

当前思考能力由供应商识别和型号规则决定。已复现：百炼连接中 `deepseek-v4-flash` 返回五档，`deepseek-v4.1-flash` 只返回 `off`；原因是现有型号正则不接受 `.1`。这是平台能力识别限制，不是新型号不具备推理能力的证据。

目标：同一端点下，新型号在匹配既定模型族模板时，用户只需添加模型 ID，即可使用模板进行真实验证，无需为每个具体型号改代码。

范围：模型配置、思考控件、AgentLoop 请求解析及版本追溯。第一期不改变 Benchmark/Judge/Worker 的实际请求行为；这些调用路径在接入相同解析器并通过测试前，不得宣称已支持模板。后续接入单列任务。

## 2. 最终用户流程

1. 用户选择供应商、协议和已有连接，输入模型 ID 或从接口列表选择。
2. 系统按供应商、协议和模型族筛选模板，自动填充唯一候选；多个候选时由用户选择。
3. 用户点击“测试并添加”；平台按模板声明的可选档位并发发起真实请求，开启思考时必须取得可观测证据，至少一个档位成功才保存协议档。
4. 模型进入可选列表；Agent 输入栏只读取实际验证成功的能力。
5. 若模型能力有差异，选择其他供应商模板后重新验证。

首次配置连接时选择一次默认模板，后续新增模型直接继承。普通新增流程不展示请求 JSON，也不要求填写每个参数。

界面示例：

```text
供应商：阿里云百炼
协议：所选连接的协议
模型 ID：deepseek-v4.1-flash
思考配置：继承连接模板
模板：该连接已选定的 DeepSeek 思考模板
状态：验证中 / 已验证 3 个档位 / 验证失败（未保存）
[选择模板]                       [测试并添加]
```

以上示例不声明该型号的具体参数已被百炼验证。模板须依据实际端点协议配置，不能仅凭模型品牌推断。

## 3. 模板选取规则

优先级固定为：模型显式覆盖 → 模型显式选择的模板 → 连接默认模板 → 供应商与协议的唯一默认模板 → 待配置。

- 模型族匹配只用于筛选适用的受控模板，绝不直接推断模型是否支持思考；最终能力仍由真实探测决定。
- 对百炼、NVIDIA 等托管多品牌模型的平台，供应商只限定可选模板集合，不足以唯一决定模型能力。
- 若连接只用于一种参数方言，可指定默认模板；混合托管连接有多个候选且无默认时，首次要求选择模板，不自动猜测。
- “待配置”与“不支持思考”必须分开显示。未知状态不能自动变成 `off`；已确认不支持思考才使用非思考模板。
- 当前请求解析仍须校验协议与模板兼容，不能因为前端可选就直接放行。

旧协议档没有显式模板时继续使用旧解析逻辑，避免一次升级改变所有已有模型行为。新建配置默认走模板流程；旧档可主动迁移。

## 4. 模板内容与职责

模板是受控配置，不包含代码、凭据、地址或任意请求体。

| 配置项 | 含义 |
| --- | --- |
| 模板 ID、名称、版本 | 稳定身份与不可变修订版本 |
| 供应商、兼容协议、模型族匹配器 | 共同限定模板适用范围；模型族匹配器只筛选模板，不推断能力 |
| 能力模式 | 不支持、仅开关、强度档位、Token 预算 |
| 可否关闭 | 明确是否允许 `off` |
| 可选档位与默认值 | 默认值必须属于可选项 |
| 参数适配器 ID | 选择已实现、经过校验的参数转换器 |
| 档位映射 | 平台选项映射为接口枚举或预算；可多对一，但界面不得伪装不同原生强度 |
| 预算约束 | 最小值、最大值、与输出上限的关系，仅预算模板需要 |
| 来源与适用说明 | 官方文档、核对日期、端点限制 |
| 探测证据要求 | 开启思考时要求 reasoning 增量或正数推理用量；无证据不得开放档位 |
| 生命周期 | 草稿、可用、停用；停用不删除历史版本 |

适配器候选包括 `enable_thinking` 开关、`thinking.type` 开关、顶层 `reasoning_effort`、`output_config.effort`、`thinking_budget` 和 `thinking.budget_tokens`。组合方式由适配器定义，不能随意拼接冲突参数。

同一供应商可有多个模板，例如百炼的不同协议、不同思考机制。模板目录的第一批参数必须逐项核对官方文档和 SDK 序列化结果，本文不将候选目录视为已经验证的配置清单。

## 5. 最小数据设计

为控制改动范围，第一期不重构现有协议档和密钥存储，不建立完整“连接实体”或可编辑模板表。模板目录以受控静态注册表交付，后续再演进为版本化管理。

### 5.1 受控模板注册表

模板以代码中的只读注册表保存 ID、名称、版本、供应商、协议、模型族匹配器、能力模式、可选档位、默认值、适配器和说明。注册表覆盖当前配置页支持的 OpenAI、Anthropic、阿里云百炼、DeepSeek、智谱、Moonshot、MiniMax、NVIDIA、火山引擎和 Google 供应商；同一托管供应商可提供多个模型方言模板，平台按模型族筛选候选，但不以名称直接判定能力。

### 5.2 协议档绑定与探测结果

`protocol_profiles` 新增 `reasoning_template_id`、`reasoning_probe` 和 `reasoning_config_version`。探测结果只保存模板版本、验证时间、通过档位和安全错误分类；不保存 API Key、上游正文、请求体或推理内容。模型 ID、端点、协议、输出上限或模板变更后，探测结果失效。任何改表均通过 Alembic autogenerate 生成迁移并人工审查。

## 6. 继承、更新与回滚

- 新增模型保存时校验默认模板存在、可用且与协议兼容。
- 模型显式覆盖后不跟随默认模板的配置变化；界面显示“自定义”。
- 继承模板的模型在新版本发布后跟随更新。发布前展示影响模型数和配置差异，避免默认模板静默改变大量模型。
- 每个回合开始时解析并冻结有效模板版本、模型配置修订号和无密钥配置快照；回合内工具循环与重试使用同一快照。
- 回合运行期间发布新模板，不改变该回合；后续新回合采用新版本。
- 模板停用或引用失效时，禁止新请求静默回退到旧型号识别；返回可读配置错误。已有冻结请求按保留版本重放，紧急安全停用另设明确拒绝策略。
- 回滚通过切回上一可用模板版本完成，不修改历史版本或已生成报告。

## 7. 请求解析与前端同源

引入一个纯配置解析入口，输入协议档授权快照，输出有效思考能力、参数适配器、模板版本及默认值。

调用链：

```text
协议档及模板绑定
  → 解析有效配置并校验
  → 模型配置页面 / agent-ui 能力投影
  → 用户选择
  → 后端校验选择并冻结请求
  → 受控适配器构建供应商参数
  → 现有 SDK 调用
```

模板生效时绕过型号能力判定，但保留参数类型、预算、协议、授权等校验。legacy 配置才进入原有规则。

仅开关的模型展示开关；档位模型展示实际可选项；预算模型展示预算说明。不得为只有开关能力的模板制造低、中、高、最高四种不同能力。

首期保持现有回合档位枚举，模板仅能选取其中支持的项。超出当前枚举的数值强度等能力属于后续契约扩展，不能通过任意 JSON 绕过。

本地思考偏好键包含用户、协议档和有效配置版本。配置更新导致旧偏好失效时，恢复合法默认值并提示；刷新不会覆盖当前仍合法的选择。

## 8. 拟议接口与权限

已生效接口如下：

| 操作 | 路径 | 约束 |
| --- | --- | --- |
| 获取可选模板 | `GET /api/profiles/reasoning-templates` | 按供应商、协议和模型 ID 返回受控摘要 |
| 测试并新增 | `POST /api/profiles/probe-create` | 验证成功后才写协议档与环境变量 |
| 测试并更新 | `POST /api/profiles/{id}/probe-update` | 验证失败时保持原配置不变 |
| legacy CRUD | `POST/PUT /api/profiles` | 保留兼容；影响模型能力的变更会使探测结果失效 |

首次选择默认模板通过配置页面完成，不要求用户手工调用接口。模型接口和 `agent-ui` 增量返回有效模板版本、配置来源、能力模式和验证说明；保留 `allowed_efforts` 等兼容投影。

错误统一沿用 AppError：缺少/非法配置为 VALIDATION，引用不存在为 NOT_FOUND，版本冲突为 CONCURRENCY，权限失败为 UNAUTHORIZED。不得返回原始供应商错误或凭据。

## 9. 自动化边界与验证状态

“自动添加”在首期指由用户选择模型与模板后自动逐档验证、写入成功配置和刷新能力；不代表自动发现模型全部能力，也不代表无人授权地批量创建模型。

- 模型列表接口只提供 ID 时，只用于选模型，不推断能力。
- 用户触发的保存会执行有上限的真实探测，五个档位并发且各自受 30 秒超时约束；探测失败不落库，后台不会自行发起付费探测。
- 界面展示验证中、已验证档位数或验证失败，并记录对应模板版本。
- 连接测试成功不等于思考参数生效；HTTP 200 不足以证明上游没有忽略参数。
- 可继续提供已有连接测试入口；自动抓取文档、智能体生成模板、批量付费探测属于后续方案，不是本期依赖。

## 10. 实施顺序与退出条件

| 阶段 | 工作内容 | 退出条件 |
| --- | --- | --- |
| P0 契约确认 | PRD/API 增量、模板字段、权限、继承和版本策略 | 接口与产品规则一致，明确第一批模板范围 |
| P1 数据与模板 | 迁移、模板版本、默认绑定、模型覆盖、审计 | 旧数据迁移后仍为 legacy；可保存、发布、回滚 |
| P2 请求同源 | 有效配置解析、AgentLoop 快照、能力投影、SDK 适配 | 新模型名无需改规则即可使用显式模板；非法选择被拒绝 |
| P3 页面接入 | 新增模型自动继承、首次模板选择、高级覆盖、能力说明 | 添加、修改、复制、切换和刷新流程完整 |
| P4 验证与发布 | 本地门禁、预发无密钥测试、授权后的真实端点验证 | 测试通过、实际验证状态如实登记，再经 PR 发布 |

P2 同时清点旧适配器调用方，未迁移的路径保持原有行为并明确标注。后续再单独推动 Benchmark 和 Judge 使用相同冻结配置。

## 11. 验收矩阵

1. 用一个不在旧名单中的模型 ID 匹配已知模型族模板，能力仍以真实探测结果为准，不依赖具体型号正则白名单。
2. 为 `deepseek-v4.1-flash` 添加百炼对应协议模板后，UI 与发送参数使用同一配置；不凭该用例假定真实上游全部档位有效。
3. 开启思考的请求只在收到 reasoning 增量或正数推理用量后登记通过；普通完成必须保留为失败证据，不能开放档位。
4. 模型显式覆盖优先；连接默认更新不覆盖自定义项。
5. 多模板连接未指定默认时明确要求选择，不误用千问模板。
6. 不支持关闭的模板无法选择或提交 off；预算不满足约束时返回 VALIDATION。
7. 无有效模板显示待配置，不显示成已确认不支持。
8. 模板更新与请求并发时，运行中回合及工具续轮保持原快照，新回合使用新版本。
9. 重复发布幂等或明确冲突；过期修订不能覆盖最新配置。
10. 旧模型默认行为不变，迁移和回滚后均可读取历史请求。
11. 模板、错误、日志和 Agent 能力响应中不出现 API Key；跨权限修改被拒绝。
12. 页面保存后无需重新登录即可刷新模型能力；合法的用户选择不被后台刷新重置。

实施代码后执行项目要求的 API lint/测试、Worker 回归、前端 typecheck/build 和迁移验证。当前纯文档变更只执行内容、链接与 diff 检查。
