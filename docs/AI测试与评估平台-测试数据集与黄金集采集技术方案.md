## 1. 目标、范围与裁决

平台要建设的是可复现的**模型测试数据集**与可验证的 **RAG 黄金集**，不是通用网页采集系统。所有外部内容在进入评测前都是候选资产；只有经过来源、授权、完整性和人工审核后，才可以发布为不可变的正式版本。

本方案覆盖三类数据生产链路及其导入入口：

1. **公开测试数据集采集**：从官方仓库、Hugging Face 固定修订、官方发布页或管理员上传的归档文件，获取 MMLU、C-Eval、GSM8K、IFEval 等标准基准的原始制品，转为平台数据集行；
2. **RAG 黄金集采集**：从已授权且已索引的知识文档快照生成或人工录入问题、参考答案和证据锚点，用于检索质量、答案正确性与模型忠实度评测。
3. **通用业务任务生产**：从已授权业务样本、业务规则、人工标注或程序化/模型辅助生成中形成非 RAG 任务，经过独立验真、审核和用途切分后发布为 DatasetVersion；数学计算、结构化抽取、指令约束等不要求先建立 KB 索引，流程见第 4.7 节。
4. **基准数据集页自动导入**：用户在 `/datasets` 选择平台维护的公开基准目录并发起导入；Worker 获取固定制品、生成行级 staging，完成后自动显示在该数据集的表格列表，审核发布前不进入评测分母。

**V2.0 明确不做**：

- 不做任何社交媒体平台、账号、评论、视频或站内搜索抓取；
- 不做登录态、Cookie、签名、反爬绕过、下载器 sidecar 或平台专用适配器；
- 不将网络搜索摘要、模型自由生成文本、第三方未校验镜像或未经审核的文档直接写入正式数据集或黄金集；
- 现行限制下，不将公开 benchmark 的训练集、开发集或测试集用于提示词样例、黄金答案生成或模型训练；第 4.4 节列出官方 few-shot 复现的待登记例外，填写 manifest 本身不构成放行；
- 不在 API 进程下载大文件、解压归档或运行代码评测。耗时导入必须进入受控 Worker 作业。

### 1.1 核心设计原则

| 原则 | 约束 |
| :--- | :--- |
| 权威优先 | 作者官方发布页/仓库是来源真相；Hugging Face 是优先分发与加载渠道，评测框架仅是执行适配渠道 |
| 制品可复现 | 每次导入固定 source revision、归档文件 SHA-256、解析器版本、切分、提示词和评分器版本；禁止跟随远端 `main` 静默更新 |
| 候选隔离 | 下载、解析、AI 生成的内容先进入 staging/review，审核发布才生成 `DatasetVersion` 或 `GoldQaVersion` |
| 证据优先 | 判定依据须可回查；通用任务可引用规则、独立程序验证、人工标注或 rubric，RAG 黄金证据必须绑定不可变 KB 文档快照和范围 |
| 职责分离 | 下载/解析器只处理制品，审核者判断事实与用途，Worker 按锁定版本评测；生成、被测、验真和评分隔离，独立性按实际模型身份核对，不能只比较 profile ID |
| 最小化处理 | 只存评测所需的题目、答案、来源清单与最小证据；敏感内容、未授权内容和不必要个人信息不入正式资产 |

## 2. 资产分层与采集来源

### 2.1 资产模型

```text
外部标准数据源 / 授权业务材料、规则与生成记录 / 已授权知识文档
             │
             ▼
    来源登记与授权校验（draft）
             │
             ▼
   不可变制品、规则和验证记录 / KB 文档快照
             │
     ┌───────┴────────┐
     ▼                ▼
标准解析/业务任务生产  黄金 QA 候选生成/录入
     │                │
     ▼                ▼
数据集候选行       问题 + 答案 + 预期证据
     └───────┬────────┘
             ▼
       人工审核与发布
             │
   ┌─────────┴─────────┐
   ▼                   ▼
DatasetVersion      GoldQaVersion
   │                   │
   └── Task.config 锁定版本 ──► Worker / 报告
```

| 资产 | 定义 | 是否可直接评分 |
| :--- | :--- | :--- |
| 数据源登记 | 逻辑来源及其官方地址、许可证、用途边界 | 否 |
| 来源制品快照 | 已下载的 ZIP/JSONL/CSV/Parquet 等原始文件及完整性信息 | 否 |
| 导入批次 | 一次解析、规范化、校验产生的 staging 行与异常清单 | 否 |
| Benchmark 数据集版本 | 已审核且具备规定判定方法的不可变任务快照；判定可为程序或受控裁判 | 仅在对应执行器和评分器已就绪时 |
| KB 文档快照 | 已授权文档的规范化文本、哈希和索引版本 | 否 |
| RAG 黄金集版本（待实现） | 已审核的题目、答案、可回答性和预期证据快照 | 仅在版本、证据与对应评分链路就绪时 |

### 2.2 合法采集来源与优先级

| 来源类型 | 允许方式 | 固定信息 | 用途限制 |
| :--- | :--- | :--- | :--- |
| 官方 GitHub/Git 仓库 | 固定 tag 或 commit 的 release/归档文件 | `repository_url`、commit/tag、release URL、文件 SHA-256 | 仅按上游许可证使用；仓库代码不等同于数据许可证 |
| Hugging Face Dataset | 使用明确数据集 ID 与 commit revision 下载制品 | dataset ID、revision commit、config/split、文件 SHA-256 | 禁止 `trust_remote_code`；镜像失效时回查官方来源 |
| 官方项目网站/对象存储 | 成员提报固定下载地址，非提报成员复核 | 发布页、下载 URL、版本号、校验和、发布时间 | 先确认版权、地域和再分发限制 |
| 管理员上传 | 上传已获授权的原始制品 | 上传人、授权凭证引用、原始文件 SHA-256、导入说明 | 仅内部可控数据；不得把不明来源文件伪装为公开基准 |
| 已授权 KB 文档 | 拟在既有 KB 导入/索引链路补充 `KbDocumentSnapshot` | document ID、snapshot ID、内容哈希、索引状态、授权范围 | 本文用于黄金 QA；其他业务测试须另行登记用途；不能以网页 URL 替代文档快照 |

网络搜索只能用来**发现**官方项目入口；搜索摘要、第三方转载页和社区网盘不是正式制品源。发现候选后，管理员必须回到作者官方仓库、发布页或许可证文件确认来源。

上表是来源设计范围，当前 Worker 下载路径仅支持获批的无凭据 HTTPS JSONL/CSV 制品；管理员原始归档上传、Parquet、压缩包和受限令牌下载不能据此视为已实现。来源提报/复核按现行成员同权规则执行，法务或数据管理员提供用途判断，不取代非提报成员的技术发布门禁。

## 3. 总体架构

### 3.1 标准数据集采集链路

```text
成员提报数据源
        │  校验来源、许可证、适用任务、版本与切分
        ▼
数据源登记（draft）
        │
        ▼
受控导入 Worker
  ├─ 下载固定制品 / 接收管理员上传
  ├─ 限制域名、大小、MIME、压缩层数与解压后总大小
  ├─ 校验上游校验和与本地 SHA-256
  └─ 写入不可变制品快照与导入审计
        │
        ▼
纯本地解析适配器
  ├─ JSONL / CSV / Parquet / 官方专用结构
  ├─ 映射 question/reference/context/options/extras
  ├─ 校验 split、标签、字段类型、重复与敏感信息
  └─ 产生 staging 行及拒绝原因
        │
        ▼
人工审核 → 发布 DatasetVersion → 任务锁定版本
```

导入 Worker 不从模型传入的 URL、Header、Cookie、路径或脚本执行下载；其来源只能是已提报并复核批准的记录。每个解析适配器是**纯本地函数**，只读取已冻结的制品字节或临时受控文件，不自行联网、不调用模型、不修改正式数据集。

### 3.2 黄金集采集链路

```text
已授权文档导入 → KbDocumentSnapshot → 索引完成
                                      │
                   ┌──────────────────┴──────────────────┐
                   ▼                                     ▼
            人工编写黄金 QA                    AI 辅助生成候选（仅 draft）
                   │                                     │
                   └────────── 证据定位与交叉校验 ───────┘
                                      │
                                      ▼
                     内容复核 / 高风险双审 / 发布版本
                                      │
                                      ▼
                 GoldQaVersion + expected_evidence 快照
```

本节描述待实现的证据化黄金版本，不能将现有 GoldQa 的可变 version 数字视为已具备此能力。RAG 黄金 QA 必须绑定已授权、已解析的不可变文档语料快照；执行检索测试前还需固定并验证索引就绪。每道题必须标明：

- `answerability`：`answerable`、`insufficient_evidence` 或 `conflicting_evidence`；
- `expected_doc_ids[]`：有可回答证据的题必填；证据不足题可为空，不能为通过非空校验编造相关文档；
- `expected_evidence[]`：`doc_id + document_snapshot_id + start/end + text_sha256`，使用固定规范化版本的文本，偏移定义为 Unicode 码点、左闭右开 `[start,end)`，哈希取该范围 UTF-8 字节的 SHA-256；不能混用字节、JavaScript UTF-16 单元或原始 PDF 页内偏移；
- `reference` 与 `required_points`：可回答题的关键事实与支持证据；证据不足/冲突题的预期限制说明和行为，不能写成无依据的确定答案；
- `corpus_snapshot_id`、原始 `source_split`、用途和 `group_id`：限定可回答性判断范围及来源组；多文档题记录全部来源组，按相互关联的组整体切分，防止一部分证据跨用途泄漏；
- `valid_until?`：适用于时效性事实；超过有效期必须新建修订版本。

`answerability` 相对于批准的语料快照判定，不随某次检索成败改写。证据不足须记录缺少的关键条件及核查范围；冲突题须保存冲突双方证据和不能消歧的依据。语料中可回答但本轮未检索到资料，是系统检索失败，不应把黄金标签改为“证据不足”。文档级相关性、段落级相关性与完整支持答案的证据组分别标注；多跳题不能把任意命中一个文档视为已找到全部答案。

## 4. 标准数据集导入设计

### 4.1 数据源登记清单

成员提报来源、由非提报成员复核。下列是设计阶段的来源信息示意，不是可直接提交的 API 请求；例如 parser `ceval_v1` 当前未注册。实际请求字段、枚举和权限以 API 为准；来源信息是导入判断与审计依据，不是模型可编辑提示词。

```json
{
  "display_name": "C-Eval",
  "source_kind": "huggingface | git_release | official_http | upload",
  "official_project_url": "https://...",
  "distribution_url": "https://...",
  "source_revision": "commit/tag/release",
  "license": "SPDX 或上游原文引用",
  "usage_scope": "internal_evaluation_only",
  "task_family": "multiple_choice | generation | code | multimodal | preference",
  "allowed_splits": ["dev", "validation", "test"],
  "expected_artifacts": [{"path": "...", "sha256": "..."}],
  "parser_id": "ceval_v1",
  "parser_version": "1.0.0",
  "notes": "测试标签公开性、上游限制与已知污染风险"
}
```

`source_revision`、制品 SHA-256、`parser_id/parser_version`、切分和许可证在发布后不可修改；修正信息只能新建来源制品快照和新的 `DatasetVersion`。只写“latest”“main”“最新版本”或只留一个 Hugging Face 页面 URL 的登记不能进入导入队列。

### 4.2 受控下载与制品安全

1. **允许列表**：只允许已审核数据源中的 HTTPS 下载地址和固定镜像域名；下载前后均记录最终 URL，重定向仍执行域名校验；
2. **资源边界**：设置单制品大小、总制品大小、解压后总大小、压缩嵌套层数、单文件数量和作业时限，超限失败为 `VALIDATION` 或 `TIMEOUT`；
3. **格式边界**：按魔数和 MIME 校验制品类型，拒绝可执行文件、符号链接逃逸、路径穿越和未知压缩格式；解压目标限定在作业唯一临时目录；
4. **完整性**：优先验证作者发布的校验和；无上游校验和时计算平台 SHA-256 并标记 `upstream_checksum_missing`，需要人工确认后才能发布；
5. **凭据边界**：受限数据集的访问令牌只由服务器密钥管理供导入 Worker 读取，绝不存入数据源 manifest、数据库行、日志、报告或浏览器；
6. **网络与执行边界**：下载器不执行制品内代码、不启用远端自定义加载器；代码题的被测模型输出也不在导入阶段执行。

### 4.3 解析与标准化

平台不试图用一个通用 CSV 映射覆盖所有基准。下表是专用适配目标，不代表当前支持。每个 `parser_id` 均须定义输入格式、允许切分、标准字段、评分前置条件和测试样例：

| 任务族 | 标准字段 | 评分前置条件 | 典型风险 |
| :--- | :--- | :--- | :--- |
| 多选 | `question, options[], answer_key, subject` | 选项顺序、输出提取、few-shot 模板固定 | 将自由文本误解析为选项、公开 test 污染 |
| 数学 | `question, reference, solution?` | 最终答案提取与数学等价归一化版本固定 | 直接字符串比较误伤等价答案 |
| 开放生成 | `question, context?, reference?, rubric/验证依据` | 无唯一答案时仍需冻结可操作标准；裁判、转换和聚合版本固定 | Judge 偏差、风格掩盖事实错误；当前必填 reference 的发布接口尚不支持此完整结构 |
| 指令遵循 | `prompt, constraints[]` | strict/loose 规则实现及版本固定 | 把不可验证主观要求算作通过 |
| 代码 | `prompt, tests, entry_point` | 独立 bwrap 代码执行器与 `pass@k` 配置 | 未隔离执行不可信代码 |
| 多模态 | `question, media_snapshot, reference` | 媒体哈希、预处理与任务特定评分器固定 | 图像缺失、媒体许可、不同预处理造成不可比 |

完整适配的 staging 校验包括：源行数与清单一致、筛选前后及拒绝行数量可核对、任务族必填字段、标签域、切分、参考/验证依据合法性、编码、重复与泄漏和制品哈希。错误行不得静默删除；报告保留稳定来源记录 ID、行号、原因和制品快照。允许多个正确答案的任务不能强制“答案唯一”；不同题共享答案 A、0 或“无法回答”也不能仅因 reference 相同而去重。

区分三种检查：相同输入及判定依据的重复、相同输入却有冲突答案、同文档/模板/仓库的近重复或用途泄漏。原始 `source_split` 保留不改名；另拟增加用途 `development/calibration/evaluation/regression/demonstration` 和来源组 `group_id`。用途与分组跨导入批次核对，开放基准按原协议保留官方切分，内部生成集按来源组划分。当前发布检查只比较本次选中行的 question/reference 精确组合及 split，不是跨版本语义去重系统；更强检查是后续门禁，不能宣称已经生效。

人工删选或修订官方题后，必须记录父记录、改动和排除清单；派生版本标为内部改编或子集，不能继续使用完整官方成绩名称。目标输入与隐藏 reference、测试程序、评分材料分别标记，适配器只能按允许字段构建目标请求，不能将整个 extras 拼入提示词。

### 4.4 测试标签与数据污染处理

- 上游 test 标签未公开或要求官方提交的基准，只能导入 dev/validation 做内部回归，结果必须标注为“非官方 test”；
- 公开多年且可能进入预训练的数据集保留为**历史可比指标**，不应用于声称模型依赖外部上下文；
- 动态或按期更新的数据集必须以发布日期和制品哈希作为独立版本，不能合并为一个浮动数据集；
- 正式计分样本不得与开发、校准、示范或训练用途混用；版本保留原始 split 和批准用途，现行标准集 train 导入限制继续执行。记录 manifest 是审计要求，不豁免第 1 节用途限制，也不允许把测试题换个 split 名用于调优；
- 公开基准不自动成为业务黄金集。业务真实性和 RAG 忠实度只能由已授权知识库与私有/受控测试文档验证。

**官方 few-shot 复现的待登记例外：** 仅对上游协议明确指定、来源和用途已核对的示范切分，提出 `official_demonstration` 用途。须冻结示范记录 ID/hash、模板、数量/选取算法及来源版本，并与正式计分样本和裁判校准集隔离；禁止正式测试题示范、用测试成绩挑示范、生成业务黄金答案或训练。该例外尚未登记 PRD/API、尚未实现门禁，当前不能启用。未获准时采用允许的无示范改编协议并明确命名，或不执行该官方协议，不能宣称已等价复现。所有获得其他用途许可的内部样例同样记录 manifest。

### 4.5 基准数据集页的自动导入

#### 4.5.1 页面与导入作业边界

目标设计以 `/datasets` 为导入入口，前端导入抽屉与 staging 发布交互仍待接线。页面只读目录、提交选择、轮询状态和展示 staging；下载、解析等在 Worker 中执行，压缩包支持另行实施。独立 `DatasetImport` 队列已有后端实现，不复用评测 `Task`，不能假装成已完成 benchmark 任务。

```text
数据集页「导入公开基准」
        │
        ▼
数据集目录筛选 + 查看来源清单
        │  选择 release、split、目标名称与目录
        ▼
POST /api/dataset-imports → 202 Accepted
        │
        ▼
Worker: 下载 → 校验 → 解析 → staging
        │
        ├─ failed：页面显示归一错误码、失败阶段和可重试提示
        └─ review_ready：自动刷新目标数据集表格，展示 staging 行和质量摘要
                                       │
                                       ▼
                         审核并发布 → DatasetVersion → 可创建评测任务
```

导入请求必须选择平台已审核的来源和 release（具体请求字段以 API 为准）；用户不能直接输入任意下载 URL、请求头、Token、解析脚本或压缩包内路径。自定义来源先由成员提报、非提报成员复核，满足来源、用途和执行能力条件后才能开放导入。

#### 4.5.2 页面场景划分

| 场景 | 用户动作 | 后端行为 | 页面结果 |
| :--- | :--- | :--- | :--- |
| 快速导入官方基准 | 选择目录中的 C-Eval、MMLU、GSM8K 等已审核条目 | 读取固定 release manifest，创建幂等导入作业 | 创建 `importing` 数据集，显示进度 |
| 按能力发现数据集 | 按语言、任务族、评分方式、许可状态、测试标签可用性筛选 | 仅检索平台目录元数据，不触网 | 卡片显示适用场景、版本、来源、风险和预计样本数 |
| 导入指定切分 | 选择 `validation` 或公开 `test`，可选 subject/子集 | 校验该 release 允许的 split 与许可证 | 只导入选中范围，并在表格中标记 split |
| 导入后人工检查 | 查看行表、来源信息、解析告警和抽样预览 | staging 行仍与 active 版本隔离 | 可删除/修订不合格行或整体拒绝导入 |
| 发布为评测集 | 点击“审核并发布” | 原子创建 `DatasetVersion`、内容哈希和审计记录 | 数据集状态变为 `active`，可用于确认卡 |
| 失败或重复导入 | 查看失败原因或再次点击同一 release | 返回同一进行中/已完成作业，或按策略重试 | 不生成重复行；失败显示 `VALIDATION`/`UPSTREAM`/`TIMEOUT` |

目录中不展示“任意网页抓取”入口。`从 URL 导入`若未来开放，第一步也只能创建 `draft` 数据源登记，经过来源、许可证与制品清单审批后才能出现“开始导入”按钮。

#### 4.5.3 表格保存语义

为同时满足“自动保存到表格列表”和“未经审核不得评分”，数据集有以下可见状态：

| 状态 | 表格可见性 | 是否可编辑 | 是否进入评测 |
| :--- | :--- | :--- | :--- |
| `importing` | 显示来源卡和作业进度，不显示不完整行 | 否 | 否 |
| `review_ready` | 显示 staging 行，行首展示 split、来源和解析告警 | 仅审核修订 | 否 |
| `active` | 显示已发布行和不可变版本号 | 正式版本只读；通过新受控导入的 staging 审核后发布新版本 | 是 |
| `failed` / `rejected` | 保留失败摘要或审计，不显示为可评分表格 | 否 | 否 |

Worker 在 `review_ready` 时将规范化结果写入与目标 `dataset_id` 关联的 staging 行表，因此用户无需下载再上传，刷新页面仍能看到表格。发布操作必须把**审核通过的 staging 行**原子冻结到 `DatasetVersionRow`；未选中、解析失败和拒绝行不能混入版本。每行至少保存 `source_release_id`、`artifact_sha256`、`source_record_id`、`split`、`parser_id` 和 `parser_version`，供表格抽屉查看，不将冗长原始制品内容送入模型上下文。

上述表格展示是目标交互，不代表前端已交付。当前已有 active_version_id 的数据集不能通过直接保存正式行或上传绕过导入流程；“复制正式版本为可编辑草稿”若需要，应另立产品/API 契约。新 staging 不影响旧 active_version_id，发布后才切换当前版本；已创建任务仍读取原冻结版本。

#### 4.5.4 内容筛选和场景标签

目录筛选不是按标题关键词“搜网页”，而是按受审计的结构化元数据组合：

| 筛选维度 | 示例值 | 作用 |
| :--- | :--- | :--- |
| 能力场景 | 通用知识、科学推理、数学、多步推理、指令遵循、代码、中文、多模态、RAG 忠实度 | 帮助用户构成覆盖矩阵，禁止用单一总分替代分项 |
| 任务族/评分器 | 多选 exact、数学等价、规则校验、LLM Judge、代码 `pass@k`、图文评分 | 只展示当前平台已支持的任务族；未支持的条目为 `planned` |
| 语言与地域 | 中文、英文、多语种、中国特定知识 | 防止把中文场景误用英文基准代替 |
| 来源与许可 | 官方/镜像、`allowed`/`review_required`/`blocked`、是否可再分发 | blocked 不可导入；review_required 完成用途核查后，由非提报成员依契约复核 |
| 测试可用性 | public test、validation only、官方提交、动态 release | 防止把无标签 test 当作本地正式 test |
| 可信度风险 | 历史污染高、测试标签受限、动态更新、Judge 偏差、需沙箱 | 在导入确认页和报告中持续展示 |
| 规模与成本 | 预计行数、媒体大小、是否需要 Worker/GPU/Judge | 超过团队配额时禁止或拆分导入 |

目标界面默认显示已批准、许可 allowed 且满足当前导入能力的条目，分别提示评分能力；默认选择允许的 validation 或公开 test，不选择 train。超大数据集通过明确的 subject/子集或待实现的采样策略控制规模；来源版本、过滤条件及最终样本清单进入 manifest。当前 Worker 支持冻结 split 和字段精确过滤，不支持任意过滤表达式或通用随机抽样；增加采样须固定算法、种子、排序和选中 ID，并标为子集协议，不能把取前 N 行写成随机抽样。

### 4.6 首批目录与解析器策略

下表是候选接入清单，不是运行目录或已支持声明。当前静态解析注册表只有 `jsonl-qa-v1`、`csv-qa-v1`；未核验生产目录中的来源授权或 release 登记状态。

| 目录条目 | 场景 | 默认导入范围 | 解析/评分策略 | 目录状态 |
| :--- | :--- | :--- | :--- | :--- |
| C-Eval | 中文通用知识与推理 | 经核对有公开标签的允许切分；非官方 test 显著标注 | 保留选项/答案键，对照官方输入与评分协议 | `planned` |
| MMLU / MMLU-Pro | 通用知识与推理 | 各自固定 release 的允许计分切分 | 各自专用适配；概率与生成协议不混称 | `planned` |
| ARC-Challenge | 科学推理 | Challenge 子集中的允许 split；子集与 split 分别记录 | 保留原选项结构，专用答案提取与评分 | `planned` |
| GSM8K | 多步数学 | 固定 release 的允许 test | 最终答案提取与数值判定，对照官方协议 | `planned` |
| IFEval | 指令遵循 | 固定版本官方输入集 | 专用指令校验与 strict/loose 聚合 | `planned` |
| TruthfulQA | 开放域真实性 | 固定 release 与明确 MC 配置 | 按该配置的官方评分器实现，生成式协议另行设计 | `planned` |
| GPQA、AGIEval、CMMLU、MATH | 专家/考试/中文/竞赛数学 | 逐一复核来源与用途后确定 | 专用 parser、执行器、评分器与许可门禁 | `planned`，来源/用途待逐项审核 |
| HumanEval、MMBench、OCRBench、MT-Bench、AlpacaEval | 代码、多模态、对话偏好 | 不默认导入 | 需要代码沙箱、媒体制品或 Judge 协议 | `planned` |

现有 `support_status=supported` 是目录导入准入标记，必须结合来源/release 批准、license.status=allowed 和已注册 parser；它不证明专用评分正确、官方复现或可入榜。许可审核状态与技术支持状态分别管理，不因可下载就认定用途允许。

拟新增能力矩阵分别记录“来源已核验、可导入、可执行、已对齐官方协议、可入榜”，每项附版本和验证记录。JSONL/CSV 能解析只证明文件格式可读；extras 中保留选项也不等于目标请求已包含选项。只有输入构建、输出提取、评分和官方样例对照全部通过，才能声明对应协议支持；缺少专用能力时拒绝该执行配置，或显式使用内部改编集。新增能力字段需先登记 API，不能直接向当前枚举写入自造状态。

### 4.7 通用业务任务的生成、验真与发布

本节补齐[基准方法方案第 6 节](AI测试与评估平台-大模型基准测试方法与榜单建设方案.md)的授权业务样本和人工/模型生成来源。它属于拟议数据生产流程，不是已上线接口；与 RAG 黄金生产共用候选隔离、审核和版本机制，但不强制所有题目都有 KB 文档、检索索引或唯一答案字符串。

```text
批准的测试蓝图 + 来源/用途登记
    → 业务样本整理 / 人工编写 / 程序生成 / 模型候选生成
    → 候选池：输入与私有判定依据分开
    → 格式、独立验真、去重与用途/来源组检查
    → 开发样本试答与难度校准 → 内容复核
    → 发布不可变 DatasetVersion 与统一任务清单
    → 按第 6.4 节交给 BenchmarkSuiteVersion / EvaluationPlan
```

| 来源/任务 | 候选产出 | 发布前判定依据 |
| :--- | :--- | :--- |
| 已授权真实业务样本 | 脱敏后的输入、来源记录和使用范围 | 领域标注、批准业务规则及必要原始证据；敏感内容先处理，不直接复制原始日志 |
| 规则计算/参数化数学 | 参数、问题、规则版本、答案候选 | 独立重算或第二实现、边界校验、单位/数值提取规则；生成器原样自报答案不算验真 |
| 结构化抽取 | 输入文本/表格、schema、字段标签 | 人工或独立程序核对字段、允许等价形式及空字段语义；schema 合法不等于字段值正确 |
| 指令约束 | 提示、约束组合和预期行为 | 可执行约束验证器及正确/错误对照输出；冲突或不可满足约束单独标注，不混入正常遵循题 |
| 文档依据问答/开放生成 | 固定材料、必答点、参考或 rubric | 人工事实审核、证据位置和评分锚点；材料直接给模型时可作为文本任务，不必走 RAG 检索 |
| 工具/多轮/环境任务 | 初始状态、目标、工具/轮次及完成条件 | 环境快照与后置条件验证器；执行适配未就绪时保留候选，不当作普通问答正式上线 |

候选记录保留 blueprint_id/revision、来源类型和稳定记录 ID、任务族/场景、语言/难度、group_id、输入制品、私有判定依据、生成器与验证器版本、验证日志及审核修订。模型生成时另存实际模型身份、提示版本、参数和费用；程序生成时保留代码版本、参数及种子。候选不是正确答案的单一事实源，生成和验真不能只复用同一次未经核对的推导。

发布门禁按任务族执行：客观题必须有已验证的答案/验证器；开放任务可无唯一 reference，但必须有可执行的评分协议；工具任务必须有可用环境与完成判定。去重和冲突检查遵守第 4.3 节；开发、裁判校准、正式计分和回归用途按来源组隔离，查看正式目标成绩后不得删改失败题来改善同一版成绩。正式清单只包含审核通过、用途允许且适配器支持的任务，发布同时保留拒绝/排除记录。

流程执行边界：Agent 辅助蓝图、生成和解释；批量生成/验真进入受控 Worker 作业。现有 testcase 生成结果可作为候选来源，但既有“确认用例”不自动等于本文独立验真或数据版本发布通过；需要在 PRD/API 登记候选来源到 staging/发布的连接。当前通用导入发布仍要求 question/reference 非空，不能给开放题填假答案绕过；支持统一任务表示及对应准入后再发布该类任务。生成候选也不能伪装成官方 release 或已执行的 benchmark。

**与首轮试点的覆盖映射：** 总方案建议的 60 道短答/规则计算、70 道文档依据问答、40 道结构化抽取和 30 道指令约束，分别由上述对应生产路径提供；70 道文档问答只有在测检索系统时才走 GoldQaVersion。数量只是候选蓝图，不能通过重复模板凑足独立样本量；冻结正式样本前核对各场景、语言、难度、来源组及验证记录。数据就绪状态与当前执行器就绪状态分别报告。

## 5. 黄金集构建与忠实度设计

### 5.1 候选生成与审核

人工录入和 AI 辅助生成都只能创建 `draft` 候选。AI 候选生成器必须输出问题、参考答案、逐事实证据范围、可回答性和不确定性；它不能发布版本，也不能补造不存在的证据。

审核者按以下顺序验收：

1. 文档授权、快照、索引状态和证据范围均存在；
2. 问题不依赖未提供的外部知识，且与 `answerability` 一致；
3. `reference` 的每个原子事实均被证据支持；对时效信息确认 `valid_until`；
4. `answerable`、证据不足和冲突证据三类题均有明确的期望行为；
5. 同源文档、近重复问题和改写题不跨 dev/test；
6. 正式候选至少由非创建者且非最后编辑者复核；高风险、时效或冲突样本由两名合格审核者独立通过。审核绑定内容 hash/revision，修改题目、答案或证据后旧批准失效。人手不足的单人例外仅可保留为诊断候选并写审计，不按双人审核正式黄金版本发布。

候选生成器冻结模型实际身份、提示版本、来源材料与预算，只能生成 draft。程序校验范围/hash/格式，独立验真者检查事实、遗漏和可回答性，人工发布者检查用途及覆盖。黄金答案的人工审核集与 Evidence Judge 校准集、正式测试集按来源组隔离；同一个模型用不同会话验真不自动构成独立来源。生成、校准与正式评测的全部调用按专家协作方案的软/硬预算口径计量，不能把估算费用写成硬上限保障。

### 5.2 黄金证据、检索结果与模型上下文

评分必须区分三份制品，不能相互补造：

| 制品 | 保存内容 | 评分用途 |
| :--- | :--- | :--- |
| `gold_evidence_snapshot`（拟议） | 审核后的黄金证据、语料版本、相关性与必答要点 | 判断数据质量、答案正确性与检索覆盖；仅评测侧可读 |
| `retrieval_trace`（拟议） | 本轮查询、引擎及降级来源、候选/重排次序、文档/段落 ID、文本快照、检索配置 | 判断检索命中与排序，定位检索失败 |
| `model_context_snapshot`（拟议） | 本轮实际送给目标模型的材料、顺序、截断/压缩结果、工具返回和请求引用/hash | 判断输出是否得到模型可见材料支持 |

检索到的文本可能被过滤、截断或压缩，不能把完整 retrieval_trace 当作已发送上下文。压缩后的内容要保留实际文本及来源映射；忠实度针对实际提供材料，压缩是否扭曲原文另行诊断。多轮/Agent 模式须记录该次回答前可见的证据范围和工具观测，不用未来轮次补充的证据倒推支持。

| 维度 | 回答的问题 | 依据 |
| :--- | :--- | :--- |
| 数据可信度 | 黄金答案在语料版本和用途下是否真实、完整、有效 | 原始来源、审核与有效期 |
| 检索质量 | 找到了多少相关材料，顺序是否合理 | retrieval_trace 对照冻结相关性与黄金证据组 |
| 答案正确性 | 核心事实和必答点是否满足任务，是否正确处理未知/冲突 | reference、required_points、黄金证据及任务规则 |
| 回答忠实度 | 输出的可核查主张是否由实际可见材料支持 | 输出原子主张与 model_context_snapshot 的支持关系 |

例如黄金资料有答案，但检索未命中，模型凭记忆答对：正确性可以通过，忠实度不能因黄金资料存在而通过。模型忠实复述了错误上下文时，也可能忠实度通过但正确性失败。[Ragas 官方 Faithfulness 定义](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/)以回答相对于 retrieved context 的支持关系为依据；本项目进一步要求该上下文确为本次送入模型的材料。

语料可回答而模型因缺检索证据拒答，可在“遵守实际证据边界”诊断中合理，但端到端任务仍可能失败；两种结论分别记录。正确性裁判和忠实度裁判使用独立输入包：后者不得接收黄金答案、未发送的黄金证据或其他裁判结论。实际上下文记录丢失时标为 `unscored`，不能用黄金证据替代；若记录完整且确认上下文确为空，则按空材料判断实际输出主张。

### 5.3 Evidence Judge 输入、输出与独立性

拟议 `evidence_policy.v1` 是 RAG 分类评分策略，尚未实现。服务端冻结任务、模型可见上下文、原始回答、主张切分版本和判定规则。两个裁判看到同一份待核查主张及完整回答，须检查切分是否遗漏关键事实；主张清单有实质遗漏或合并错误时先修订清单并重新评分，不能靠漏抽主张提高支持率。

以下是合法形态的虚构输出示例，引用仅用于展示结构，不是真实评分。正式 JSON Schema 须登记 API：

```json
{
  "schema_version": 1,
  "policy_version": "evidence_policy.v1",
  "sample_id": "demo-rag-001",
  "context_snapshot_id": "demo-context-001",
  "status": "scored",
  "response_behavior": "answered",
  "claims": [{"claim_id": "claim-1", "text": "退款期限为七天。", "verdict": "supported", "evidence_refs": ["demo-context-001#span-1"]}],
  "reason": "该主张由本轮实际可见材料支持。"
}
```

`status` 分为 `scored / unscored / needs_review`；`response_behavior` 分为 `answered / abstained / mixed`，将模型拒答与裁判无法判分区分。每条主张的 verdict 为 `supported / unsupported / conflicted`，分别表示有支持、缺少充分支持、与上下文明确冲突。服务端检查主张 ID、覆盖、版本和证据引用；supported/conflicted 须有有效证据，unsupported 可为空。输出异常不填 0，不信任模型自报总分。引用存在只证明结构合法，语义支持仍需独立评审和人工校准。

生成、被测、裁判使用隔离用途和上下文；实际供应商、模型标识/版本及可知部署信息写入快照。不同 profile 指向同一模型仍是同源，正式独立裁判默认排除已知与目标同模型身份，生成器自验只作筛查，不作黄金验真唯一依据。裁判之间已知同源不计作独立来源，未知身份标注并按冻结的赛道条件决定资格；研究自评单列。裁判默认无任意工具、专家信箱或工作区写权限，待评文本中的指令不改变评分规则。

### 5.4 校准、分歧复核与放行

1. 在独立人工标注校准集上验证主张切分、三个 verdict、拒答行为及错误方向；覆盖正确但无上下文支持、忠实但事实错误、截断丢证据、冲突、无事实主张和提示注入等案例。冻结人工一致性检查、错误容忍及发布标准。裁判自报 confidence 不是已校准正确概率；删除未经验证的固定 0.85 门槛。
2. 首个候选自动策略为两个独立裁判逐主张盲评；两者有效且标签一致时采纳。任一标签或行为分歧时增加第三个独立裁判，对同一输入先盲评；三个结果全部有效且各待判标签均有至少两票一致才产生自动结论，否则 `needs_review`。无来源独立的裁判或复核预算不足时保持待复核，不能降低票数门槛。
3. 每裁判槽位仅对超时、暂时上游错误或结构无效最多额外重试一次，采纳第一个有效结果，不为获得更高支持率反复调用。失败为 `unscored`；初评、重试、第三裁判和人工修订分别留存。人工复核须基于相同实际上下文，新增证据不能偷偷进入旧运行评分输入。
4. 人工可以审查全部裁判一致但可疑的样本；预先规定的高风险强制复核不因多数一致而跳过。改变主张切分、上下文、rubric 或裁判配置生成新评分修订；目标实际输入变化则重新执行目标。
5. 默认正式汇总要求全部应评样本和必需主张有有效终判；未解决的评分失败/待复核保留 null。当前有效子集均分只能作为条件诊断值并附覆盖率，不能直接入正式榜单。存在合理 `not_applicable` 的指标按预先冻结条件剔除并单列计数，不把未知评分伪装为不适用。

此分类策略不直接套用 benchmark 的 `judge_policy.v2` 数值中位数规则。若需要对 RAG 正确性采用 0–4 rubric，可沿用基准方法方案的版本化标准分转换；分类票决、数值维度和业务验收分别定义，禁止按 enum 序号平均。

### 5.5 指标、分母与报告

每次报告给出计划数、目标完成/失败数、有效上下文记录数、可评分数、待复核数、未评分数及各指标不适用数，并冻结 macro/micro 聚合。候选默认如下：

| 指标 | 定义及分母 |
| :--- | :--- |
| `claim_support_rate` | 每题 supported 主张数 / 全部可核查主张数；题内主张全部终判才有效；场景默认对有效适用题取 macro 均值 |
| `unsupported_claim_rate` / `conflicted_claim_rate` | 同一分母上的 unsupported / conflicted 比例；三类穷尽已判主张，不能隐藏冲突类 |
| 评分覆盖率 | 全部必需评分已有效终判的样本数 / 按协议需要评分的样本数；另列原始及当前 needs_review/unscored 数 |
| `needs_review_rate` | 当前仍待复核样本数 / 应评样本数；另列曾触发复核的比例，避免人工处理后丢失复核成本 |
| `answer_correctness` | 按黄金任务规则判定正确性/覆盖，报告其独立评分及覆盖率，不由忠实度推导 |
| 拒答 precision / recall | 冻结“不应给确定答案”的阳性定义；TP 为应保留/拒答且实际满足行为，FP 为可回答却拒答，FN 为应保留却给确定结论；分别为 TP/(TP+FP)、TP/(TP+FN) |
| 检索 recall/MRR 等 | 按冻结文档/段落粒度和相关性规则；无相关材料的证据不足题不进入召回分母，但进入独立不可回答任务统计 |

纯拒答或无可核查事实主张时，主张支持率为 null 且标记 `not_applicable`，不设为 100%；空输出按目标失败规则处理，不能算成功拒答。拒答 precision/recall 分母为零时显示不适用及计数，不填 0 或 1。`mixed` 行为按冻结的任务判定器处理：保留措辞中仍夹有无依据确定答案，不能只凭“我不确定”几个字算正确拒答。

例如计划 100 题中 20 题尚待复核，其余 80 题主张全部支持，报告写“有效子集支持率 100%，终判覆盖 80%，待复核 20，正式评分未完成”，不能写成全量忠实度 100% 或占正式名次。目标服务失败的效用另按基准方案计量，不给评分器未知结果填零。报告与榜单由统计事实生成，Agent 仅解释；未生成过目标回答的检索任务，其忠实度显示“未测量”。

### 6.1 不可变性

数据源、制品、导入批次、正式数据集和黄金集的版本关系如下：

下图是概念关系：已有实现使用 DatasetImport 表示导入批次；GoldQaVersion 等对象仍是待实现名称，不能将图中概念名直接用作现有 API 或表名。

```text
DatasetSource
  └─ SourceArtifactSnapshot (内容哈希、revision、license)
       └─ ImportRun (parser/version、split、校验结果)
            └─ DatasetVersion / DatasetVersionRow

KbDocumentSnapshot
  └─ GoldQaVersion / GoldQaVersionItem / expected_evidence
```

目标架构中，正式评测只读冻结版本。benchmark 已有 `DatasetVersion/Row` 并在建任务时锁定数据版本；当前 RAG 仍按 gold_qa_id 读取可变 GoldQaItem，GoldQa.version 不等于不可变行快照。`GoldQaVersion/Item`、文档/语料/索引快照、实际检索与上下文记录需补充共享模型和 Alembic，再由建任务事务锁定引用。Worker、重跑、报告和基线须统一改为读取这些冻结事实后，才能声明黄金版本可复现。现有旧 RAG 报告保留其真实可追溯边界，不能追补一个版本号就称已具备快照。

### 6.2 生命周期

| 状态 | 含义 | 可否评测 |
| :--- | :--- | :--- |
| `draft` | 来源/制品/候选刚创建，尚未完成审核 | 否 |
| `reviewing` | 正在进行完整性、许可证、事实或证据审核 | 否 |
| `accepted` | 来源或候选被接受，可参与发布 | 否 |
| `active` | 正式版本已发布且未过期 | 是 |
| `deprecated` | 许可证撤回、发现错误、过期或被修订版本取代 | 仅保留历史报告，不得新建任务 |
| `rejected` | 无法确认来源、授权、完整性或证据 | 否 |

撤回或到期先禁止旧资产的新使用并记录原因，不为撤回动作伪造一个可用替代版本。只有经修订、重新审核的内容才发布新版本；历史报告保留版本、内容 hash、评分口径和最小审计记录。数据错误导致的重算要覆盖全部受影响模型并形成新结果修订；删除正文后明确不可恢复范围，不能静默重写旧报告。

### 6.3 许可证、隐私与保留

1. 许可证检查是发布门禁，不是备注字段；特别是 `NC`、`SA`、受限测试、禁止再分发和数据用途限制，均需在导入前由管理员/法务确认；
2. 公开可下载不表示允许重新分发。平台默认只保留评测需要的最小制品和元数据，并在 UI/导出中遵守上游限制；
3. 含个人信息、未成年人信息、秘密、凭据或无关敏感文本的文档不得进入黄金集；
4. 数据制品、文档快照、审核理由与导入日志分别应用保留策略。正文清理后，历史报告保留哈希、版本和审计摘要，不能声称仍可恢复原文；
5. 所有下载令牌、上传授权文件和服务器凭据均只在受控后端使用，严禁进入日志、WS 事件、报告或模型上下文。

### 6.4 数据资产向基准套件和评测计划的交接

本节是拟议 `evaluation_asset_manifest.v1` 交付契约，采用[总方案第 5.2 节](AI测试与评估平台-大模型基准测试方法与榜单建设方案.md)的统一任务表示。它不是新 REST 请求或现有数据库字段的声明，须在实现前登记 PRD/API 和共享模型。

**身份规则：** case_id 是首次登记后持久化的任务身份；case_version 在输入、判定依据或执行约束改变时递增。来源 namespace + 原始记录 ID 用于查找稳定映射，同一来源重复导入沿用任务身份；缺稳定源 ID 时由平台首次分配并保存映射，不能拿可变行号当身份。DatasetVersionRow 的 ID 仍是该版本中的存储定位。不同来源是否为同一任务需经溯源确认建立别名，不能凭参考答案相同就合并；近重复以来源组和查重结果处理。

| 统一交付字段 | 来源或映射 | 使用方与校验 |
| :--- | :--- | :--- |
| case_id、case_version、case_hash | 来源记录到任务身份的持久映射；hash 覆盖输入、判定依据引用/hash及约束 | 执行、评分、统计按同一任务版本关联；hash 不能代替身份 |
| asset_kind、asset_version_id、asset_hash、row_locator | DatasetVersion 或 GoldQaVersion 及对应不可变行 | 定位并核对真实发布内容，不能只给 dataset_id 或可编辑 active 指针 |
| scenario、task_family、language、difficulty、group_id | 蓝图、专用适配和审核标签；多来源组保留关联清单 | 套件选样、覆盖检查和统计分组；不得由执行器临时猜测 |
| source_split、usage、provenance | 原始切分、批准用途、来源版本/记录、生成及验证记录 | 拦截开发/示范/校准混入正式计分，保留官方/改编身份 |
| input.messages、public_context_refs | 文本题 question/context 经冻结适配器映射；其他任务保留完整结构 | 仅此公开输入及批准工具资料可送目标；不能全文序列化 extras |
| private_evaluation | reference/required_points、scorer_id/version 或 rubric、隐藏验证器/证据制品与 hash | 仅评分侧读取；正确性所需证据不自动成为目标上下文 |
| constraints、capability_requirements | 工具、媒体、上下文、环境、终止条件及任务必需能力 | 验证 runner/模型是否支持；任务要求与赛道预算冲突则拒绝计划，不静默降级 |
| review_revision、review_refs、publication_status、validity/usage_scope | 已发布版本的审核、内容 hash、有效期和允许用途 | 交接时及启动前复验当前撤回/授权状态，快照不绕过撤销 |

当前 question/reference/context 可映射简单单轮文本，但不能承载完整工具轨迹、媒体或多轮任务。新版 manifest 必须能解析真实的私有制品并检查权限/hash；只有一个可读字段名或 extras 占位不算完成交付。现有 m3-initial scorer 标记不能自动映射成某个专用官方评分器。

**一次交付的完整清单：** manifest 记录 schema_version、manifest_id/hash、资产版本清单、适配器 ID/version、统一任务列表的制品引用/hash、条目数与确定性顺序、按场景/用途/来源组的计数、批准/排除记录及允许的评分协议。每项任务包含上表字段；大清单可单独存为受控不可变制品，但消费方必须能验证和读取，不能只传摘要或总题数。散列采用登记的规范化编码版本，不用重新序列化后的偶然顺序作为证据。

| 环节 | 输入与职责 | 冻结产物 |
| :--- | :--- | :--- |
| 采集/发布 | 验真、审核、版本和可用能力检查 | 数据资产版本 + 完整任务 manifest；不决定榜单权重或名次 |
| BenchmarkSuiteVersion | 引用资产版本/任务键，选择场景与子集，规定权重及输入/评分协议 | 不可变套件和任务池；一个正式运行中同一任务版本默认只计一次，显式重复另记 repeat_id |
| EvaluationPlan | 从套件按协议确定正式样本，校验任务约束、模型能力及预算 | 最终有序样本 manifest、全部资产/套件 hash、模型/参数、评分、种子/采样和重复策略 |
| Task / EvaluationAttempt | Worker 按计划调用目标，保留采样/重试/重复身份 | plan_id、case_id/version、sample_id、attempt/repeat_id 与实际输出/用量；既有 Task 状态机保留 |
| 评分、报告、榜单 | 只读取同一计划与样本结果；版本不匹配拒绝聚合 | 评分修订、统计事实和可追溯榜单快照；数据发布本身不代表入榜 |

sample_id 标识计划中的一个计分/采样位置；多次生成、运行重复和传输重试分别编号，不能通过新增 case_id 将同一题的十次生成当成十道独立题。最终清单须支持同套件各模型使用相同样本/重复设计并进行配对统计。

**交接失败处理：** 缺字段或适配器、不可读取制品、hash/版本不符、用途或权限失效、隐藏依据进入公开输入、必要评分器未就绪时，拒绝创建/启动该计划并给出可核对原因；运行中发现则标记受影响结果无效或未完成，不回读最新版本补齐。当前任务 API 自动冻结 active_version_id 的规则继续有效；新增 suite/plan 引用和跨资产取样须先登记契约，不能由客户端任意指定旧/新版本绕过当前门禁。

接收方保存全部引用与校验结果；修订数据创建新资产/任务版本并重新形成套件或计划。仅改评分规则时按总方案允许复用原输出，但须核对公开输入及执行约束 hash 一致，保存原执行 case_version 与新评分版本的关联，不能重写原执行身份；改变目标输入或执行条件必须重新执行目标。采集模块不自行计算综合分、置信区间或排名。

## 7. 安全、可靠性与可观测性

| 维度 | 设计 |
| :--- | :--- |
| 长短任务分离 | 成员提报/非提报成员复核为短事务；耗时导入、候选生成和评分由受控 Worker 作业执行，API 不等待终态；尚未支持的作业能力先定契约 |
| 下载防护 | HTTPS/域名允许列表、每跳重定向校验、资源上限、内容类型与 SHA-256 校验；拒绝脚本执行与路径逃逸 |
| 代码防护 | HumanEval 等代码集只能通过独立代码执行器运行生成答案，必须走现有 bwrap 沙箱；未实现前不得对外开放该任务族 |
| 失败语义 | 来源/授权/格式问题为 `VALIDATION`，上游 4xx/5xx 为 `UPSTREAM`，作业超时为 `TIMEOUT`；禁止用空数据或 mock 成功降级 |
| 日志 | 仅记录数据源 ID、版本、制品哈希前缀、导入行数、错误码和耗时；不记录题目正文、答案、下载 Token、授权材料或完整 URL 参数 |
| 可观测性 | 记录下载成功率、校验失败率、解析拒绝率、审核采纳率；重复检查标明精确/语义及覆盖范围；报告黄金终判覆盖、复核/未知数量、上下文缺失和预算结算状态 |

## 8. 测试策略

| 层级 | 必测场景 | 验证方式 |
| :--- | :--- | :--- |
| 来源登记 | 缺官方地址、revision、许可证或允许切分时拒绝 | API/服务单测 |
| 下载制品 | 重定向越界、哈希不符、过大压缩包、路径穿越、未知 MIME | 下载器单测与恶意 fixture |
| 解析器 | 每个 parser 的标准行、空字段、标签错误、编码错误、题目重复、split 泄漏 | 固定离线制品 fixture |
| 版本冻结 | 修改当前编辑行或远端数据后，已建任务读取同一版本快照 | API + Worker 集成测试 |
| 黄金证据 | 可回答题缺证据拒绝；证据不足题允许空相关文档但要求核查依据；冲突题保留双方证据；包含 emoji 的范围验证不得混用 UTF-16/码点 | KB/Gold fixture |
| 忠实度边界 | 黄金有答案而实际上下文无依据、检索结果被截断、忠实复述错误材料、实际上下文日志缺失 | 分别验证正确性、忠实度和 unscored，禁止回填黄金材料 |
| 裁判独立性 | 三个不同 profile 指向同一模型、身份未知、裁判读到其他裁判初评、待评内容要求改规则 | 模型身份与输入包隔离测试 |
| 复核与分母 | 80 个有效/20 个待复核、第三裁判失败、复核预算不足、所有裁判一致但命中强制复核条件 | 条件成绩与正式门禁分开；未知不记零，不降低裁判数 |
| 分类与空集合 | 无事实主张、纯拒答、空输出、mixed、无相关文档、拒答指标分母为零 | 空输出不是成功拒答；不适用指标 null，拒答与评分失败分开 |
| 用途隔离 | 同文档跨导入、跨版本改写、多文档关联组、同题冲突答案、不同题同一个答案 | 同源用途冲突被发现；不按 reference 单独误删；检查范围如实标注 |
| few-shot | 尚未登记例外、示范引用不在批准清单、示范与测试重叠、以 manifest 备注试图放行 | 现行限制拒绝；未来例外测试绑定契约启用条件，不提前开放 |
| 编辑发布 | 已发布版本直接保存/上传、staging 过期 revision、候选内容编辑后使用旧审批、官方题被修订 | 旧快照不变；新版本重审；改编/子集名称不冒充完整官方协议 |
| 能力状态 | 仅通用 CSV parser 却声明 IFEval 官方支持、选项只保留 extras、评分器未实现 | 不得标为官方对齐/可入榜；未支持执行拒绝或明确改编 |
| 通用任务生产 | 无 KB 的规则计算/抽取/指令候选、开放题无唯一答案、生成器自报未经核对的 reference | 使用任务族验证器/rubric 独立验真；缺依据拒绝发布；不填假 reference、不强制建 KB |
| 任务身份 | 同来源重复导入、行号重排、输入修改、不同来源相同答案 | 稳定 case_id 映射，语义改动递增 case_version；存储行 ID 不作跨版本身份 |
| 资产交接 | manifest 少字段、私有制品缺失/hash 错、用途冲突、未知 scorer、相同任务重复入池 | suite/plan 准入拒绝；重复按显式 repeat/sample 身份处理，不扩大独立题数 |
| 端到端追溯 | 同样本给两个模型，数据更新后重跑/重评，报告引用旧版本 | 输入冻结不漂移；case/sample/attempt 可关联；评分修订与目标重跑按变化内容区分 |
| 许可证治理 | 用途不兼容、禁止的分发动作、授权撤回或过期资产 | 按实际使用条件拒绝对应动作；不把许可证缩写本身当作一律禁用 |
| 回归 | 自动回归使用离线固定制品；真实来源连通性、供应商与 Linux 执行环境另做受控验收 | 纯文档不触发应用 CI/CD；代码按本地门禁执行 |

## 9. 分期实施计划

| 里程碑 | 内容 | 前置条件 |
| :--- | :--- | :--- |
| **M0：契约闭环** | 目录/导入已有基础契约和共享模型；待登记本版新增黄金快照、证据分类、用途、能力矩阵、复核/分母及前端流程；few-shot 例外保持待定 | PRD/API 增量完成裁决，新字段不能先落代码 |
| **M1：标准与业务数据生产** | JSONL/CSV 导入后端已存在；补前端、通用业务候选/验真/发布、稳定任务身份与统一 manifest，登记来源和专用适配 | 覆盖总方案 B1 的官方及授权内部任务；按第 6.4 节完成数据→套件→计划交接验收 |
| **M2：黄金集与检索快照** | 在现有 GoldQa/RAG 检索基础上补文档/语料/索引版本、证据定位、候选审核、GoldQaVersion、用途隔离和任务冻结 | 文档授权明确；证明旧任务不随黄金行/知识库编辑漂移 |
| **M3：专用评分与治理扩展** | 按场景实现专用输入/评分器；RAG 补生成模型调用、实际上下文记录、Evidence Judge、校准与复核、报告及入榜资格 | 各场景独立验收；RAG 必须先有真实回答和上下文证据，代码/多模态执行另行评审 |

上述 M0–M3 是本文工作包，不等同 PRD 的同名全平台里程碑。与基准方法方案 B0–B4、专家协作方案 P0–P4 的依赖在实施计划中逐项关联：数据后端基础可独立推进；RAG 证据评分不需要等动态多 Agent 团队全部上线，静态受控裁判调用即可实现；多 Agent 的价值另做预算对齐比较。

对齐顺序为：总方案 B0 确定蓝图/赛道，本文 M0 登记交接与用途；B1 与本文 M1 共同交付通用任务和正式样本清单；B2 消费可判分任务和独立校准资产；B3 只使用合格执行/统计结果；B4 的 RAG 依赖本文 M2/M3 对应证据和执行能力。文本试点不以前置完成 RAG 黄金系统或动态专家协作为条件。

每个里程碑单独分支与 PR。新增数据模型必须修改 `backend/shared/models.py` 并生成 Alembic 迁移；不得通过路由层临时 JSON 拼装快照，也不得把导入作业伪装为已成功评测任务。

## 10. 风险与处置

| 风险 | 等级 | 处置 |
| :--- | :--- | :--- |
| 数据集镜像或默认分支变化导致结果漂移 | 高 | 固定 revision、制品 SHA-256、解析器版本与正式数据集版本 |
| 上游许可证与内部/商用用途冲突 | 高 | 发布前许可证门禁；不清楚即 `rejected`，不以“公开可下载”推定许可 |
| 公开 test 已被模型训练污染 | 高 | 标注历史可比性；引入动态集和私有/受控 KB 集，不将其当作 RAG 忠实度证据 |
| 代码样本执行攻击宿主 | 高 | 仅 bwrap 隔离执行；执行器未就绪时不支持代码任务族 |
| LLM Judge 与被测模型存在同源偏差 | 高 | 实际模型身份核对、输入隔离、独立人工校准、有界复核；未知来源标注，不以 profile 不同或自报高置信度证明独立 |
| 黄金证据代替实际上下文导致忠实度虚高 | 高 | 三份证据制品分开存储；缺少实际上下文记录时 unscored，不用黄金内容补齐 |
| 难题待复核后被排除，形成选择性高分 | 高 | 条件诊断值附覆盖；默认全量有效终判才正式汇总/入榜；保留复核和未完成原因 |
| Benchmark 与黄金集混用 | 高 | 数据源用途、任务族、版本和权限隔离；正式黄金集只引用 KB 文档快照 |
| 答案标签、公式或选项解析错误 | 中 | parser fixture、上游行数/哈希核验、人工抽样和新版本修订 |
| 大文件导入拖垮 API 或磁盘 | 中 | Worker 队列、制品资源上限、临时目录清理与失败可重试 |

## 14. V2.2 实现记录（目录治理、导入租约与 staging 发布）

### 14.1 已实现闭环

```text
成员提报目录来源 / 固定 release
        │  draft → reviewing → approved（不同成员复核）
        ▼
POST /api/dataset-imports（只引用已批准 release）
        │  request_fingerprint 幂等、冻结 manifest/域名/哈希/筛选条件
        ▼
DatasetImport 独立队列
        │  FOR UPDATE SKIP LOCKED + 15 分钟 lease + attempt 记录
        ▼
Worker：HTTPS/重定向/私网地址检查 → SHA-256 → 固定 JSONL/CSV parser
        │
        ├─ VALIDATION / UPSTREAM / TIMEOUT → failed；仅后两者可 retry
        └─ review_ready → staging 行（稳定 UUID + staging_revision）
                                      │
                      非提报成员按 revision 审核、编辑、选择
                                      ▼
            原子发布 DatasetVersion / DatasetVersionRow → Dataset.active_version_id
                                      │
                                      ▼
        新建 benchmark Task 时锁定该 version；Worker 仅读取该版本行
```

### 14.2 当前安全与可信度边界

- Worker 不接收浏览器传入的 URL、Cookie、Header、Token、路径或解析脚本；作业 manifest 在 API 创建时冻结来源允许域名、release manifest、筛选条件与 parser 版本。
- 下载只允许无凭据 HTTPS、审核域名及同样受审核的重定向目标；下载前拒绝 loopback、私网、链路本地与保留地址；单制品上限 50MB，制品 SHA-256 不匹配即失败。
- 当前仅注册 `jsonl-qa-v1` 与 `csv-qa-v1` 两个受控 parser；API 与 Worker 共用注册表，未注册 parser 不能标记 release 为 supported。该检查只覆盖 parser 准入，不能据此推断已验证 task_family、专用输入、评分和官方协议的全部能力；后续须增加场景适配门禁。
- staging 行用稳定 UUID 而非可变行号选择；保存和发布要求 expected_staging_revision，编辑与发布须由非提报成员执行。发布事务内校验选中行的题目/答案非空、split 存在及 question/reference 精确组合重复；跨 split 检查仅覆盖该批选中行，不包含跨版本、近重复、同源组或校准集泄漏。
- 发布后 `DatasetVersionRow` 是不可变快照；手工上传、正式行编辑和删除不能绕过已有 `active_version_id`。任务创建把 `dataset_version_id/version_no` 写入配置快照，benchmark Worker 仅读取它。
- 当前发布路径的 scorer_version 为 `m3-initial`，不能视为各官方基准专用评分器已冻结；正式评测还需按基准方法方案冻结任务输入、提取器、裁判/评分和样本 manifest。
- 现有 RAG 执行器读取 GoldQaItem，执行检索并记录命中等指标；EvalItem.output 保存检索指标 JSON，不是目标模型生成回答。该链路尚不能据此计算回答正确性、忠实度或拒答质量。

### 14.3 已知后续工作

4. 如要支持压缩包、Parquet 或需要登录授权的来源，必须另行评审资源上限、许可和解析器，不得扩展通用下载器能力。
